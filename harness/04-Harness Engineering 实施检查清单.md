✅ Harness Engineering 实施检查清单

# 阶段一：启动期 —— 建立最小可行Harness
> 目标：让AI完成一个“端到端可闭环”的小任务

- [ ] 定义最小任务单元
  - 选择边界清晰的任务（如“生成API文档”、“修复样式Bug”）
  - 创建独立目录（如 `/tasks/autodoc`）
  - 编写 `TASK.md`：明确输入、输出、验收标准

- [ ] 划定行为边界
  - 限制Agent仅能访问指定目录
  - 禁止修改核心模块（如 `/src/core`）
  - 设置 `.gitignore` 或权限控制，防止越界

- [ ] 创建结构化上下文
  - 根目录下建立 `AGENTS.md`，包含：
    - 项目目标
    - 架构概览
    - 修改流程说明
  - 模块级上下文（如 `src/auth/AGENTS.md`）提供接口规范与依赖关系

- [ ] 部署基础约束机制
  - 配置 ESLint/Prettier 强制代码风格
  - 使用 pre-commit Hook 阻止含 `console.log` 的提交
  - 启用 Docker 沙箱隔离运行环境

> 📌 关键成果：AI可在隔离环境中完成一个PR，且不破坏主分支

---

# 阶段二：验证期 —— 实现自动反馈闭环
> 目标：建立“输出即验证”的自动化质量门禁

- [ ] 接入CI/CD流水线
  - 配置 GitHub Actions / GitLab CI 等工具
  - 所有Agent提交必须触发流水线

- [ ] 配置自动化测试
  - 单元测试覆盖率 ≥ 90%
  - 接口测试通过 OpenAPI Schema 验证兼容性
  - 集成端到端测试（如使用 Puppeteer）

- [ ] 启用安全与合规检查
  - SAST扫描（如 Semgrep）检测代码漏洞
  - DAST扫描（如 ZAP）检测运行时风险
  - SBOM 自动生成与依赖审计 

- [ ] 打通可观测性系统
  - 集成日志查询接口（如 LogQ）
  - 提供监控面板访问权限，供AI读取系统状态
  - 配置错误日志自动回传至Agent上下文

> 🔄 闭环目标：Agent提交 → CI失败 → 返回错误 → Agent自动修复 → 重新提交

---

# 阶段三：扩展期 —— 支持多任务并行
> 目标：支持多个Agent在不同任务中协同工作

- [ ] 分层上下文管理
  - 项目级、模块级、任务级文档分层组织
  - 实现“渐进式披露”，避免上下文过载

- [ ] 权限与任务隔离
  - 使用 Worktree 或沙箱实现多任务并行
  - 为不同任务分配独立Agent实例

- [ ] 任务调度与优先级管理
  - 建立任务队列机制
  - 支持高优先级任务插队或抢占资源

- [ ] 统一工具访问标准
  - 接入 MCP（Model Control Protocol）服务器（如 Stripe Toolshed）
  - 统一Agent调用工具的方式，提升可维护性 

> 🌐 成果：多个Agent可同时处理登录优化、文档生成、Bug修复等任务

---

# 阶段四：成熟期 —— 自主熵减与持续进化
> 目标：系统具备自我清洁与免疫能力

- [ ] 部署“错误模式库”
  - 记录常见失败案例（如空指针、依赖冲突）
  - 转化为Linter规则或自动修复策略
  - 实现“让Agent永不犯同样错误” 

- [ ] 启用“Doc Gardening Agent”
  - 定期扫描文档是否过时
  - 自动更新 `AGENTS.md` 和接口说明
  - 防止“上下文腐化”（Context Rot）

- [ ] 实施熵治理（Entropy Management）
  - 定期重构AI生成代码
  - 删除冗余文件与无效逻辑
  - 建立“Agent Captain”角色负责流程治理 

- [ ] 建立评估体系（Evals）
  - 超过 89% 团队已实现可观测性，但仅 52% 建立评估机制 
  - 定义“做得对不对”的量化标准（如任务成功率、修复耗时）

> 🧠 终极目标：系统像JVM的GC一样，自动清理混乱，持续进化
